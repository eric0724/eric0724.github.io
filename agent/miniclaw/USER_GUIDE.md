## 1. 系統概述

### 1.1 Miniclaw 是什麼？

Miniclaw（小龍蝦）是一個讓玩家透過自然語言指令操控電腦的 AI 助手系統。你可以在手機或網頁上輸入指令，AI 會自動解析並在電腦上執行操作。

### 1.2 系統架構

```
┌─────────────┐      WebSocket       ┌──────────────┐      Python       ┌──────────┐
│   手機/網頁  │ ◄──────────────────► │  server.js   │ ◄──────────────► │  pyautogui │
│   (前端 UI)  │                      │  (Node.js)   │                  │  (自動化)  │
└─────────────┘                      └──────────────┘                  └──────────┘
                                             │
                                             ▼
                                      ┌──────────────┐
                                      │  AI 模型      │
                                      │  (Gemini/     │
                                      │   OpenAI/     │
                                      │   Ollama)     │
                                      └──────────────┘
```

### 1.3 支援平台

- **Windows**（主要開發平台）
- **Mac**（部分功能支援）
- **Android**（Termux 環境）
- **Linux**（基礎功能）

## 2. 快速開始

### 2.1 下載與安裝

1. 前往 [GitHub Releases](https://github.com/eric0724/eric0724.github.io/releases)
2. 下載 `miniclaw-executor.zip`
3. 解壓縮到任意資料夾（建議 `C:\miniclaw\`）

### 2.2 首次啟動

**Windows 使用者：**
1. 進入解壓後的資料夾
2. 雙擊 `openminiclaw.bat`
3. 等待自動安裝完成（首次會安裝 Node.js、ngrok）
4. 瀏覽器會自動開啟 Miniclaw 網頁

**Mac/Linux 使用者：**
```bash
cd app
npm install
node server.js
```

### 2.3 連線測試

1. 在網頁中輸入 ngrok 網址（openminiclaw.bat 會自動填入）
2. 點擊「🔍 測試連線」
3. 看到「✅ 終端連線正常」即可開始使用

## 3. 大廳 UI 完整操作指南

### 3.1 7 個折疊面板說明

#### 🖥️ 群組 1：終端連線

**功能：** 管理與本地執行器的連線狀態

**操作項目：**
- **連線狀態**：顯示當前是否連線成功
- **ngrok 網址**：輸入 ngrok 提供的公開網址
  - 格式：`https://xxxx-xxxx.ngrok-free.app`
  - 點擊「重新連線」按鈕更新連線
- **診斷燈號**：
  - 🟠 HTTP 通道：顯示本地伺服器狀態
  - 🟠 WebSocket：顯示 WebSocket 連線狀態
  - ngrok：顯示 ngrok 網址是否設定
- **完整執行端運作**：開關控制是否允許執行自動化腳本
- **關閉執行器**：遠程關閉執行器（需終端連線）

**常見操作：**
```
1. 連線失敗時，檢查 ngrok 網址是否正確
2. 確認執行器視窗是否開啟（應看到「Server started」）
3. 點擊「重新連線」嘗試重新建立 WebSocket
```

#### 🧠 群組 4：AI 設定

**功能：** 調整 AI 模型的行為與觸發設定

**操作項目：**

- **自動故障分流**：當主要 AI 失敗時自動切換到備用 AI
- **自訂 System Prompt**：輸入自訂的 AI 行為指令（選填）
- **手勢自動觸發巨集**：
  - ✅ 開啟：辨識到手勢後自動執行對應巨集
  - ❌ 關閉：僅顯示辨識結果，不執行巨集

**手勢開關詳細說明：**
```
開啟狀態：
  1. 你在畫面上繪製手勢（如 M）
  2. 系統辨識為 [MATCHED] M
  3. 自動執行巨集「遊戲手勢_M」
  4. 巨集內容會自動操作滑鼠/鍵盤

關閉狀態：
  1. 你在畫面上繪製手勢（如 M）
  2. 系統辨識為 [MATCHED] M
  3. 僅顯示「手勢辨識成功：[MATCHED] M（自動觸發已關閉）」
  4. 不會執行任何巨集
```

## 4. 手動模式（Manual Mode）

### 4.1 什麼是手動模式？

手動模式讓你可以使用任何網頁 AI（ChatGPT、Claude、Gemini 等）來處理指令，Miniclaw 只負責執行你貼上的 AI 回覆。

**適用場景：**
- 想使用特定 AI 模型
- AI 金鑰額度耗盡
- 需要更精確的控制

### 4.2 啟用步驟

1. 在初始化流程中選擇「🔗 方式 D：手動模式」
2. 或在大廳中重新引導設定

### 4.3 使用流程

```
1. 在輸入框輸入指令（如：「幫我截圖」）
2. Miniclaw 會產生提示詞（已包含系統上下文）
3. 複製提示詞，貼到網頁版 AI（如 ChatGPT）
4. AI 回覆後，複製回覆內容
5. 貼回 Miniclaw 的輸入框並按送出
6. Miniclaw 會解析並執行指令
```

### 4.4 實戰範例

**步驟 1：輸入指令**
```
使用者輸入：「幫我截圖目前畫面」
```

**步驟 2：複製提示詞**
```
[系統提示詞]
你現在是『Miniclaw 小龍蝦控制中樞』的專屬本地端 AI 助手...

[使用者指令]
幫我截圖目前畫面
```

**步驟 3：AI 回覆（範例）**
```
聊天: 正在為您截取畫面...
指令: miniclaw:screenshot
```

**步驟 4：貼回並執行**
- 複製 AI 回覆
- 貼回 Miniclaw 輸入框
- 按送出
- 系統會自動截圖並顯示

## 5. 校準流程與自動降級

### 5.1 為什麼需要校準？

Miniclaw 使用 AI 視覺來辨識畫面元素的位置。校準是為了讓 AI 知道「我要點擊的按鈕在哪裡」。

**校準時機：**
- 首次使用新遊戲或應用程式
- 畫面解析度改變
- 視窗位置移動

### 5.2 三種校準模式

**模式 A：GPT-4o Vision 自動校準**
- AI 直接分析截圖，找出元素位置
- 優點：快速、不需額外設定
- 缺點：可能受光線/畫面變化影響

**模式 B：手動座標輸入**
- 你手動輸入元素的 x, y 座標
- 優點：最精確
- 缺點：需要手動測量

**模式 C：視覺模板比對**
- 截取元素圖片作為模板
- 系統在畫面上搜尋匹配位置
- 優點：穩定、不受文字變化影響

### 5.3 自動降級手動校準

當 AI 自動校準連續失敗 3 次時，系統會自動降級到手動模式：

**觸發條件：**
```
1. AI 回傳的座標超出螢幕邊界
2. 點擊後確認失敗（元素未正確觸發）
3. 連續 3 次重試都失敗
```

**應對方法：**
```
系統會提示：
「⚠️ 自動校準失敗，請改用手動模式
請在畫面上點擊元素的确切位置，
或使用座標輸入方式。」

你可以在大廳的「手動模式」中：
1. 截圖查看當前畫面
2. 手動輸入座標（如：x=500, y=300）
3. 或使用滑鼠點擊工具選取位置
```

### 5.4 常見問題

**Q: 校準後點擊位置偏移？**
A: 可能是視窗移動或解析度改變，請重新校準

**Q: AI 找不到元素？**
A: 嘗試使用「視覺模板比對」模式，截取更清晰的元素圖片

**Q: 校準失敗怎麼辦？**
A: 系統會自動降級到手動模式，依照提示操作即可

## 6. 手勢辨識實戰操作

### 6.1 M/W/O/V 手勢繪製教學

Miniclaw 支援 4 種手勢辨識，對應遊戲中的常用操作：

#### M 手勢（攻擊/確認）
```
繪製方式：
1. 從左上角開始
2. 畫一個「M」字形
3. 包含 2 個山峰

範例軌跡：
    /\
   /  \  /\
  /    \/  \
 /          \
```

#### W 手勢（移動/跳躍）
```
繪製方式：
1. 從左上方開始
2. 畫一個「W」字形
3. 包含 3 個山谷

範例軌跡：
\    /\    /
 \  /  \  /
  \/    \/
```

#### O 手勢（環繞/防禦）
```
繪製方式：
1. 畫一個圓形或橢圓形
2. 封閉的軌跡
3. 大小約 100-200 像素

範例軌跡：
  /\
 /  \
|    |
 \  /
  \/
```

#### V 手勢（技能/特殊）
```
繪製方式：
1. 從上方開始
2. 畫一個「V」字形
3. 包含 1 個山谷

範例軌跡：
\      /
 \    /
  \  /
   \/
```

### 6.2 視覺軌跡記錄機制

**visual-trail 技能功能：**
1. 記錄滑鼠移動軌跡（時間戳 + 座標）
2. 分析軌跡形狀（波峰、波谷、對稱度）
3. 與模板比對，辨識手勢類型

**繪製技巧：**
- 速度：均勻速度繪製，不要過快
- 大小：手勢範圍約 200x200 像素
- 清晰度：避免抖動，軌跡要連貫

### 6.3 巨集觸發流程

```
1. 繪製手勢（如 M）
   ↓
2. visual-trail 記錄軌跡（100ms 內）
   ↓
3. gesture-recognizer 分析軌跡
   ↓
4. 辨識結果：[MATCHED] M
   ↓
5. server.js 攔截並解析
   ↓
6. 檢查手勢開關狀態
   ↓
7. 若開啟 → 執行巨集「遊戲手勢_M」
   ↓
8. macro-recorder 播放巨集
   ↓
9. 滑鼠/鍵盤自動操作
```

### 6.4 實戰範例：遊戲手勢操作

**場景：遊戲中的攻擊動作**

**步驟 1：錄製巨集**
1. 開啟遊戲，停留在要操作的畫面
2. 在 Miniclaw 輸入：「啟動錄製器」
3. 執行滑鼠點擊攻擊按鈕
4. 停止錄製，儲存為「遊戲手勢_M」

**步驟 2：設定手勢開關**
1. 進入大廳 → AI 設定
2. 開啟「手勢自動觸發巨集」
3. 儲存設定

**步驟 3：實戰使用**
1. 在遊戲中繪製 M 手勢
2. 系統辨識後自動執行攻擊巨集
3. 遊戲角色執行攻擊動作

**進階技巧：**
- 組合技：M → W → O 連續手勢
- 熱鍵巨集：手勢 + 鍵盤快捷鍵
- 條件觸發：特定畫面才觸發

## 7. 常見問題與疑難排解

### 7.1 連線問題

**問題：終端顯示「離線」**
```
解決方案：
1. 確認執行器視窗是否開啟
2. 檢查 ngrok 網址是否正確
3. 點擊「重新連線」按鈕
4. 若仍失敗，關閉執行器並重新啟動
```

**問題：WebSocket 連線中斷**
```
解決方案：
1. 檢查網路是否穩定
2. ngrok 免費版每小時會更換網址
3. 重新執行 openminiclaw.bat 取得新網址
```

### 7.2 AI 金鑰問題

**問題：AI 回應緩慢或失敗**
```
解決方案：
1. 檢查 API 金鑰是否有效
2. 確認網路可連線至 Google/OpenAI
3. 切換到備用 AI（自動故障分流會自動處理）
4. 使用本地 Ollama（需先安裝）
```

**問題：Gemini Token 過期**
```
解決方案：
1. 系統會自動降級到 API Key
2. 若仍失敗，重新登入 Google 帳號
3. 或手動輸入新的 API Key
```

### 7.3 手勢辨識問題

**問題：手勢辨識不準確**
```
解決方案：
1. 繪製時保持均勻速度
2. 手勢範圍不要太小（建議 200x200 像素）
3. 避免在複雜背景上繪製
4. 重新錄製巨集，確保觸發時機正確
```

**問題：手勢辨識成功但巨集未執行**
```
解決方案：
1. 檢查「手勢自動觸發巨集」開關是否開啟
2. 確認巨集名稱是否正確（遊戲手勢_M/W/O/V）
3. 查看巨集是否已錄製
4. 檢查巨集腳本是否有誤
```

### 7.4 自動化腳本問題

**問題：腳本執行失敗**
```
解決方案：
1. 確認 Python 環境已安裝
2. 檢查必要套件：pyautogui, Pillow, pynput
3. 查看執行日誌（chat_history.txt）
4. 確認目標視窗是否開啟且未最小化
```

**問題：滑鼠點擊位置偏移**
```
解決方案：
1. 重新執行校準流程
2. 檢查螢幕解析度是否改變
3. 使用「手動座標輸入」模式
4. 確認遊戲視窗未移動
```

### 7.5 效能問題

**問題：系統回應緩慢**
```
解決方案：
1. 清除對話歷史（對話過長會影響效能）
2. 檢查是否有僵死進程（系統會自動清理）
3. 關閉不必要的背景程式
4. 檢查網路延遲（AI API 呼叫）
```

**問題：日誌檔案過大**
```
解決方案：
1. 系統會自動封存超過 5MB 的日誌
```
