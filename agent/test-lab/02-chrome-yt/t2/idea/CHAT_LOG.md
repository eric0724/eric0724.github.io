### 二、新方向討論

**原始想法**（使用者提出）：
> AI 分析影片，找出使用者在哪幾秒按下按鈕，把點擊前的畫面擷取下來讓 py 分析

**關鍵決策**：
- 不讓 AI 回傳座標（之前測試過 GPT 座標不準）
- AI 只負責找「點擊的秒數（時間點）」
- Python 負責找游標位置並裁切

**流程設計**：
```
1. AI 分析影片 → 找出點擊秒數（不回傳座標）
2. Python 取出該秒的影格（Hover 狀態）
3. Python 往前倒帶 0.8s 取出影格（Normal 狀態）
4. Python 用 OpenCV 在 Hover 影格上找游標位置 (cx, cy)
5. 以 (cx, cy) 為中心裁切兩張範本
```

### 四、根本問題確認

**使用者提供的游標截圖**（`img23.png`）顯示：
- 影片中的游標非常模糊（影片壓縮造成）
- 游標只有約 16x20px，邊緣完全糊掉
- 任何形狀比對方法都無法可靠識別

**嘗試過的自動偵測方案**：
1. OpenCV 遮罩樣板比對（箭頭游標） → 找到 OBS 遞迴預覽中的小游標
2. 多類型游標（箭頭 + 手掌 + I-Beam） → I-Beam 誤判純色背景
3. 光流法 / 差分幀 → 概念上與 AI 找座標相同，只是換工具

---

### 五、最終決策：改做視覺化標記工具

**放棄從影片偵測游標**，改成讓使用者直接在螢幕上標記：

> 做一個視窗，像自動點擊器那樣可以放好幾個點。
> 視窗上有兩種：拉（拖曳區域）和點擊（點位）。
> 使用者放完後按截圖，自動截取各標記位置的乾淨圖片。
> 之後可以換到其他畫面繼續增加標記。

**優點**：
- 完全不需要影片
- 完全不需要游標偵測
- 使用者直接精準標記，100% 正確
- 截圖是當下螢幕畫面，無模糊問題

**待確認細節**：
1. 點擊點的截圖尺寸：固定 120x60px 還是使用者自訂？
2. 拖曳區域：直接以矩形裁切？
3. 換畫面後繼續加標記到同一清單？
4. 是否要為每個標記設定名稱？
