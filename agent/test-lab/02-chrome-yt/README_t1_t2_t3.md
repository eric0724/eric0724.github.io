# 02-chrome-yt — 三種方式對比

這裡測試了三種方式來「讓 AI 理解螢幕上的 UI 元素位置」，進而產生自動化腳本。

---

## t1：AI 直接看截圖回傳座標

**原理：** 把螢幕截圖傳給 GPT-4o Vision，問「Windows 搜尋圖示在哪裡」，AI 直接回傳座標。

**流程：**
```
1. 全螢幕截圖
2. 問 GPT-4o：「找到 X 元素，回傳座標」
3. GPT 回：{"x":100, "y":200}
4. 用 pyautogui 去點那個位置
```

**問題：**
- GPT 座標不準（偏移 10~50px）
- 需要紅點校準，但紅點標在 AI 看到的截圖上還是不準
- 放大截圖改善有限

**結論：** GPT-4o Vision 不適合精準定位，只能識別「大致區域」。

**檔案：**
- `t1/scripts/calibrate.py` — 校準工具（AI 找位置 + 截範本）
- `t1/scripts/chrome_yt_task.py` — 用範本圖案比對點擊

---

## t2：使用者手動標記

**原理：** 不讓 AI 找座標，使用者自己在螢幕上標記「這裡要點」「這塊是區域」。

**流程：**
```
1. 打開標記工具
2. 點「+ 點擊點」→ 出現半透明遮罩 → 點擊確認位置
3. 點「+ 拖曳區域」→ 拖曳框選
4. 每個標記填說明（例如：「Windows 搜尋圖示」）
5. 按「截圖全部」→ 自動裁切所有標記位置的小圖存成範本
```

**優點：**
- 100% 精準（使用者親自標的）
- 不消耗 API
- 直接截圖當下畫面，無模糊問題

**缺點：**
- 需要手動標記（但比 AI 校準快）
- 只適合「靜態 UI」（遊戲動態畫面不適用）

**檔案：**
- `t2/scripts/capture_tool.py` — 主工具（已實作，可用）

---

## t3：錄製真實操作

**原理：** 錄製使用者的實際操作（滑鼠點擊 + 鍵盤輸入），加上文字說明，整包傳給 AI 理解。

**流程：**
```
1. 玩家在「主要訊息」框寫整體說明
2. 按「開始錄製」
   → 監聽滑鼠點擊：記座標 + 截圖
   → 監聽鍵盤：記按鍵序列
3. 按 F8 或「停止」結束
4. 在每筆紀錄下方輸入說明
5. 用「+ 新增點/區域」補充錄製沒捕捉到的地方
6. 按「複製給 Miniclaw」產生 prompt
7. 貼到 Miniclaw，告訴 AI 要產出什麼程式
```

**優點：**
- 錄製真實操作流程，AI 完整理解行為
- 主訊息 + 個別說明，描述更清楚
- 可補充靜態標記（結合 t2 的方式）
- 輸出 JSON 存檔，可重複使用

**用途：**
- 遊戲輔助腳本（告訴 AI 操作順序）
- 自動化工作流程（告訴 AI 每個步驟）
- 教 AI 寫測試腳本（示範操作路徑）

**檔案：**
- `t3/scripts/recorder.py` — 主程式

---

## 三種方式對比表

| | t1 | t2 | t3 |
|---|---|---|---|
| **資料來源** | AI 看截圖猜座標 | 使用者手動標記 | 錄製真實操作 |
| **精準度** | 低（偏移 10~50px） | 高（100% 精準） | 高（真實操作） |
| **速度** | 慢（每次問 AI） | 快（一次標完） | 中（錄完後編輯） |
| **API 消耗** | 高 | 無 | 無（傳給 AI 是玩家決定） |
| **適用場景** | ❌ 不推薦 | 靜態 UI 自動化 | 動態操作流程、遊戲 |
| **輸出** | 範本圖片 | 範本圖片 | prompt + JSON |

---

## 推薦使用

- **自動化辦公任務（固定 UI）** → 用 **t2**（快速、精準）
- **遊戲輔助、動態流程** → 用 **t3**（錄製操作 + 說明）
- **需要 AI 理解複雜行為** → 用 **t3**（完整 prompt 給 Miniclaw）

---
